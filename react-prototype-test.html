react-prototype-test

Updated 1 Nov 2026Links 0 in · 4 out#test

Testing the overlay on a React prototype

Two builds of the same Vite + React app are published beside this note. They
differ in one line of vite.config.js and that one line is the whole story.

What to open

These are links, which is the only way to reach them: a page published as-is
stays out of the vault panel, the browse listing, the tag pages and the graph,
because it has no frontmatter, no tags and no outline to put there. A note is
how a reader gets to one, and this note is that.

Should work:

  • react-relative/index.html — Vite, built with base: "./"
  • angular-relative/index.html — Angular, built with --base-href ./

Should be blank, and the build report should say why:

  • react-default/index.html — Vite's stock config. Every reference it makes
    is root-absolute (/assets/index-*.js), which only resolves when the site is
    at the root of its own domain.
  • angular-default/index.html — Angular's stock config. This one is subtler:
    its references are relative, so every file it needs was published beside
    it, and <base href="/"> then sends the browser to the root for all of them.
    Its published output is identical to the working build's.

What to try on the working one

  1. Drop a pin on the heading or a bullet. Those do not change, so the pin
    anchors to the text. Resize the window: it should follow the words.
  2. Switch screens (Overview / Settings) and come back. The pin should be
    on the screen it was left on, and not on the other one.
  3. Reload on #/settings. A pin left there should come back there.
  4. Drop a pin on the counter paragraph — "This paragraph has changed N
    times." It changes every three seconds. The pin stays where you put it and
    the panel reports the anchor as lost, which is the intended trade: the pin
    says where, the panel says the text has changed.
  5. Open the panel and check the comments list reads sensibly across both
    screens.

What this is testing

The overlay marks a page's blocks when it loads. An app has rendered nothing
at that point, so the marking now repeats whenever the document changes —
that is what makes step 1 work at all. And because every screen of an app
shares one published file, a pin records the browser's own URL, which is what
makes step 2 work.

Known, and not a bug in the app

react-default publishing as a blank page is the publisher dropping
root-absolute references. It currently does so silently — the build report
says nothing about it, which is the part worth fixing.
